# Reproducibility and local build

The prebuilt browser demos and paper are provided directly; they do not need a build step for ordinary use.

### Verify the exact Python experiment

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 scripts/run_experiment.py
```

### Verify the browser JavaScript reference

```sh
node tests/test_browser_core.cjs
node tests/test_authoring_core.cjs
```

### Rebuild both standalone browser apps

```sh
python3 tools/build.py
python3 scripts/build_web.py
python3 tools/build.py --check
python3 scripts/build_web.py --check
python3 scripts/verify_release.py
```

### Rebuild the paper

The canonical Markdown sources are `core-papers/Portable_Evidence_Runtime.md` and `core-papers/Validation_and_Publication_Review.md`. Rebuild the plain text and PDF with installed Pandoc and LaTeX:

```sh
bash scripts/build_paper.sh
```

A PDF reader is the only requirement for the shipped PDF. Pandoc and LaTeX are **build-time tools**, not dependencies of the shipped standalone HTML apps.

### Browser offline probe (optional test tool)

Requires optional Playwright and Chromium tooling (the applications themselves require neither):

```sh
python3 -m pip install -r requirements-browser.txt
python3 -m playwright install chromium
```

Run:

```sh
python3 scripts/browser_offline_probe.py
```

The script creates an offline browser context before opening the local `file://` standalone page, checks the allowed and refused results, verifies that an invalid expected root blocks support, and records network requests. Output is saved in `experiment/results/browser_offline_probe.json`. If administrator policy blocks `file://`, the probe records that failure and tests the identical HTML in memory. It also tests export/import in a fresh context. Neither outcome is equivalent to a physical cross-device transfer.

### Integrity receipts

`scripts/verify_release.py` checks rebuilt standalone files against their source templates and the stored fixture expected root. It does **not** attest the author, secure the complete ZIP from a malicious rewriter, or prove source truth. For public distribution, publish a final ZIP digest through a separately trusted channel.

### Release file inventory

After the final builds and test runs, regenerate and check the full Git-visible
release inventory:

```sh
python3 scripts/release_manifest.py --write
python3 scripts/release_manifest.py --check
```

`SHA256SUMS` covers all release files except itself and ignored local files.
Tests that rewrite result JSON or screenshots intentionally change these receipts.
Check the downloaded inventory before regenerating results. CI checks the original
inventory before running tests. These digests are not publisher signatures.

The manuscript copies in `paper/` are generated by `scripts/build_paper.sh`; edit
only the canonical Markdown sources in `core-papers/`. PDF bytes can vary across
TeX versions and creation timestamps even when the text is unchanged.

The standard-library-only runtime, CLI and core tests need Python and Node.
Paper builds additionally need Pandoc, XeLaTeX, and DejaVu fonts. CI executes the
core tests and a separate Chromium job; it does not rebuild the PDFs.
